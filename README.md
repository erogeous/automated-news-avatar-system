# 自动化新闻数字人系统

这是一个独立的新闻口播生产工作台：输入 1–10 条新闻链接，由后台读取正文、整理事实并生成约 4 分钟的中文口播稿，经人工定稿后生成配音，再交给数字人模型完成音画匹配并输出视频。

## 项目状态

当前处于 V1 立项与架构阶段。本文档和 [产品需求文档](docs/PRD.md) 是后续开发的范围基线。

## V1 业务流程

```text
创建项目 → 录入 1–10 条新闻链接 → 读取与清洗正文
→ 人工确认来源 → 生成 900–1100 字口播稿 → 人工定稿
→ 生成授权音色配音 → 人工试听 → 数字人渲染
→ 查询状态 → 预览和下载最终视频
```

V1 不包含素材库检索、B-roll 匹配、栏目包装、字幕、转场、自动剪辑和多平台发布。

## 核心原则

- 项目独立开发和部署，不依赖“包办一条龙”工作台。
- 口播稿的核心事实必须能回溯到原始新闻。
- 未定稿的内容不得进入正式配音。
- 文稿、音频和数字人视频绑定同一稿件版本。
- 文本、配音和数字人通过可替换的 Provider Adapter 接入。
- 声音克隆和数字人形象必须使用有效授权。

## 建议技术方案

- 前端：React + TypeScript + Vite
- 后端：Node.js + TypeScript
- 数据库：SQLite，保留迁移到 PostgreSQL 的能力
- 长时任务：持久化任务表 + Worker，后续可迁移 Redis/BullMQ
- 开发存储：本地文件；生产存储：对象存储
- 外部模型：带超时、重试、幂等和回调验签的适配器

## 里程碑

1. M1：Web/API/Worker、SQLite、数据迁移、状态机和健康检查。
2. M2：10 条链接、SSRF 防护、来源选择、口播稿生成和定稿。
3. M3：配音和数字人适配器、试听、异步渲染、预览和下载。
4. M4：集成测试、失败恢复、日志、用量和部署文档。
