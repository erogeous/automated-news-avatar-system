# 自动化新闻数字人系统产品需求文档

- 文档版本：V1.0
- 当前阶段：需求基线
- 产品形态：内部 Web 工作台
- 目标产物：约 4 分钟的中文数字人新闻口播视频

> 后续需求补充：见 [独立线上应用与素材库需求](./PRODUCT_REQUIREMENTS_NEXT.md)。该文档记录 2026-09-03 讨论的新增方向，不代表已经实现；与本文件早期范围冲突时，以补充需求为后续规划依据。

## 1. 背景与目标

内容编辑每期通常会获得 5–7 条新闻稿件，极端情况下最多 10 条。本产品将打开链接、提取正文、整理事实、生成口播稿、生成配音和数字人渲染收口到一个可追溯、可审核、可恢复的工作台。

核心目标：

- 一次接收 1–10 条新闻链接。
- 自动获取标题、来源、时间与正文。
- 仅根据选中来源生成 900–1100 字的中文口播稿。
- 支持人工修改、定稿和版本记录。
- 调用授权音色生成可试听的配音。
- 调用授权数字人完成音画同步。
- 显示步骤、进度、失败原因和最终产物。

## 2. 成功指标

- 可访问的普通新闻页面正文提取成功率不低于 90%。
- 口播稿首次生成后 90% 以上落在 900–1100 个汉字。
- 配音与定稿文本一致，不允许跨版本错配。
- 所有长时任务都能查询状态、显示错误并手动重试。
- 在供应商正常的前提下，从定稿到提交数字人的人工操作不超过 3 分钟。

## 3. 用户与权限

V1 仅设置“内容编辑”角色，暂不建设复杂 RBAC。编辑可以管理口播项目、新闻来源、稿件、配音和数字人任务。供应商 API Key 只通过服务端环境变量配置，不在浏览器中展示。

## 4. 范围

### 4.1 V1 必须完成

- 口播项目列表与详情
- 最多 10 条新闻链接的录入与校验
- 安全的网页抓取与正文提取
- 来源查看、选择、手工补入和失败重试
- 口播稿生成、字数与时长预估
- 稿件版本与人工定稿
- 配音生成、试听和重新生成
- 数字人任务提交、轮询/回调、预览和下载
- 任务日志、错误展示和手动重试

### 4.2 V1 明确不做

- 素材库、向量检索与 B-roll
- 栏目包装、字幕、背景音乐和自动剪辑
- 内容发布与平台数据回收
- 多租户、计费、审批流和组织架构
- 系统自主训练声音或数字人模型

## 5. 主流程

1. 编辑创建口播项目，填写名称和 1–10 条新闻链接。
2. 系统校验 URL，拒绝本机、局域网和非 HTTP/HTTPS 地址。
3. 后台并发读取网页，保存原始 URL、最终 URL、标题、来源、时间和正文。
4. 编辑检查读取结果，排除不参与成稿的来源。
5. AI 对选中内容去重、合并，生成 900–1100 字口播稿。
6. 编辑修改稿件，系统实时显示汉字数与估算时长。
7. 编辑定稿，系统创建不可变的稿件版本。
8. 编辑选择授权音色、语速和发音词典，生成配音。
9. 编辑试听；如有问题，修改稿件或参数后重新生成。
10. 试听通过后，编辑选择数字人、画面比例与背景，提交渲染。
11. 后台通过供应商回调或轮询更新任务状态。
12. 渲染成功后显示视频预览、时长、生成时间和下载入口。

## 6. 异常处理

- 网页登录、反爬或动态渲染：标记失败，允许重试或手工粘贴正文。
- 多条新闻事实冲突：标记冲突，不允许 AI 自行裁决。
- 稿件超出目标字数：提示压缩或扩写，但允许人工强制定稿。
- 配音错读：允许修改发音词典或重新生成。
- 供应商超时：使用幂等键重试，禁止重复创建计费任务。
- 数字人失败：保留口播稿与音频，只重试数字人阶段。

## 7. 页面需求

### 7.1 项目列表

展示项目名称、编号、创建/更新时间、当前阶段、新闻条数、稿件版本、配音状态和视频状态，支持新建、查看、复制和归档。

### 7.2 项目工作区

顶部显示四步进度：

```text
1. 新闻来源 → 2. 口播稿 → 3. 配音 → 4. 数字人
```

新闻来源步骤包含 10 个链接输入位、批量读取、单条重试、正文预览、手工补入和“参与成稿”开关。

口播稿步骤包含可编辑正文、汉字数、估计时长、来源覆盖、重新生成、版本比较、定稿和事实引用面板。

配音步骤包含音色、语速、发音词典、生成进度、试听、下载、版本绑定和重新生成。

数字人步骤包含形象、背景、画面比例、排队/渲染状态、供应商任务 ID、错误信息、成片预览、下载和重试。

## 8. 文稿生成规则

- 默认输入 5–7 条新闻，最多 10 条。
- 目标 900–1100 个汉字，默认语速按每分钟 250 字估算。
- 包含开场、主体、自然过渡和结尾。
- 合并重复事实，但不丢失来源对应关系。
- 事实与观点分离，不将单一来源的推测改写为事实。
- 数字、日期、人物、机构与地点保留原始来源。
- 无法确认的内容使用审慎表述或标记待审，不允许模型补写。
- 口播正文不包含 Markdown 标题、写作说明或不会被朗读的标记。

## 9. 核心数据模型

- `Project`：项目编号、名称、阶段、状态、目标时长和时间。
- `SourceArticle`：输入/最终 URL、标题、来源、发布时间、正文、内容哈希、读取状态和是否选中。
- `ScriptVersion`：版本、内容、汉字数、估算时长、状态、来源快照和定稿时间。
- `VoiceRender`：稿件版本、供应商、音色、语速、状态、任务 ID、音频路径、时长和错误。
- `AvatarRender`：稿件版本、配音 ID、供应商、形象、比例、状态、任务 ID、视频路径和错误。
- `JobEvent`：项目、任务、事件类型、负载和时间。

## 10. 状态机

```text
sources_draft → sources_ready → script_draft → script_approved
→ voice_rendering → voice_ready → avatar_rendering → completed
```

任一执行阶段都可进入 `failed`，重试时回到失败前阶段。长时任务使用 `queued → running → succeeded | failed | timed_out`。

## 11. API 范围

- 项目：`POST/GET /api/projects`、`GET /api/projects/:id`
- 新闻：`POST /api/projects/:id/sources`、`POST /api/projects/:id/sources/fetch`、`POST /api/sources/:id/retry`
- 稿件：`POST /api/projects/:id/scripts/generate`、`POST /api/projects/:id/scripts`、`POST /api/scripts/:id/approve`
- 配音：`POST /api/scripts/:id/voice-renders`、`GET /api/voice-renders/:id`、`POST /api/voice-renders/:id/retry`
- 数字人：`POST /api/voice-renders/:id/avatar-renders`、`GET /api/avatar-renders/:id`、`POST /api/avatar-renders/:id/retry`
- 回调：`POST /api/provider-webhooks/avatar/:provider`
- 系统：`GET /api/health`、`GET /api/capabilities`、`GET /api/projects/:id/events`

## 12. 非功能需求

### 安全

- 新闻抓取必须防止 SSRF，拒绝本机、局域网、云元数据地址与非 HTTP/HTTPS 协议。
- 每次重定向都重新校验目标。
- API Key 只保存在服务端，日志不记录密钥。
- Webhook 必须验签并防止重放。

### 可靠性

- 外部调用都有超时、有限重试和指数退避。
- 创建付费模型任务必须带幂等键。
- 后台重启后能恢复未完成任务。
- 任务状态以本地数据库为工作台显示依据。

### 可观测性

- 记录请求 ID、项目 ID、任务 ID、供应商、耗时和结果。
- 保存模型用量与估算成本。
- 为正文读取、文稿、配音和数字人分类错误码。

## 13. 数据与合规

- 保留每个项目使用的新闻来源快照和原文 URL。
- 原文快照仅用于内部生产与事实追溯，不再公开分发。
- 声音克隆保留权利人、用途、有效期和撤回状态。
- 数字人形象保留肖像授权信息。
- 对外发布时按适用规则标识 AI 生成或合成内容。

## 14. 验收标准

- 可输入 1–10 条 URL，空提交、超限或非 HTTP/HTTPS 地址被拒绝。
- 每条来源独立显示状态，单条失败不阻断其他来源。
- 口播稿只使用选中且读取成功的来源，并显示字数和预估时长。
- 未定稿脚本不能生成正式配音。
- 定稿后修改会创建新版本，不覆盖历史稿件。
- 音频和视频都可回溯到具体稿件版本。
- 配音任务和数字人任务不阻塞 HTTP 请求。
- 只有试听通过的配音能进入数字人阶段。
- 服务重启后数据不丢失，失败任务可从当前阶段重试。

## 15. 待决策项

1. 配音供应商、API 协议、授权音色 ID 和授权记录。
2. 数字人供应商、API 协议、数字人 ID 和肖像授权。
3. 默认成片是 9:16 还是 16:9。
4. 口播模式是“多条新闻盘点”、“同主题专题解读”，还是两种都保留。
5. 数字人供应商是否支持直接上传音频；如果只接受 URL，需要签名的临时公网访问地址。
